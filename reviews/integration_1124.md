## 아직 사람이 해야 하는 것

1. **정답지를 `agent-v1` 도구로 확인한다 (11/20 결정 5).** AI 도구는 정답지를 읽을 수 없어 하지 않았다. `agent-v1`과 병합본의 `season_filter`는 서로 다르다. 기간 문자열 549개 중 33개에서 결과가 갈린다. 예:

   | 입력 | `agent-v1` | 병합본 |
   |---|---|---|
   | "Christmas?" , "christmas." | 315개 | 0개 |
   | "2009/12", "2010.11" | 315개 | 0개 |
   | "easter holiday" | 315개 | 0개 |
   | "season", "festive season", "연말" | 0개 | 315개 |
   | "november", "december" (연도 없음) | 0개 | 315개 |
   | "2011년 크리스마스" | 0개 | 315개 |

   그래서 `tests/test_answer_key.py`는 `agent-v1` 체크아웃에서 돌려야 한다.

   ```bash
   git worktree add ../agent-v1-check agent-v1
   cd ../agent-v1-check
   H3_ANSWER_KEY=<레포 밖 정답지 경로> python -m tests.test_answer_key
   ```

   실패하는 문항이 있으면 정답지를 고칠지 팀이 정한다. 고치면 SHA가 달라진다 (계획 §3.4는 "판정 불가").
2. **`agent-v1` 태그를 원격에 올린다:** `git push origin agent-v1`.
3. **이 브랜치를 `main`에 병합한다.**
4. **H3 채점 시트를 만든다.** 형식은 README의 "H3 grading sheet"에 있다. 채점자 2명이 따로 채점하고 합의 점수를 적는다.

- **문제 제기:** "규칙이 수천 개", "다수가 우연"은 이 데이터의 결과와 다르다. 주 규칙은 189개이고, 셔플 null의 우연 규칙 비율은 0%다. 문장을 결과에 맞춘다.

- **검증과 본페로니:** 시간 안정성(H1)과 우연 규칙 점검(§3.3)은 다른 것이다. README Method 2의 문장을 나눠 쓴다.
