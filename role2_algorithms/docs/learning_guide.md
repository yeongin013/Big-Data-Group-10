# 이해를 위한 순서

## 1단계: 입력과 손계산

`examples/baskets.json`을 연다. 상품을 얼마나 샀는지와 관계없이 한 장바구니에 있는지만 센다. 예제에서 a는 5개 장바구니, b도 5개, 두 상품이 함께 있는 장바구니는 4개다.

`models.py`의 `BasketDataset.from_rows()`는 상품을 문자열로 통일하고 정렬·중복 제거한다. 정렬은 `sorted()`를 사용한다. 정렬 알고리즘을 별도로 구현하지 않는다. 이 과정은 알고리즘 실험 전에 한 번 수행한다.

## 2단계: A-Priori를 먼저 읽는다

파일: `basket_mining/algorithms/apriori.py`

1. `item_counts`: 전체 장바구니에서 단일 상품 빈도를 센다.
2. `frequent`: 최소 등장 횟수 이상인 상품만 남긴다.
3. 각 장바구니에서 frequent에 속하는 상품만 남긴다.
4. `combinations(retained, 2)`로 쌍을 만들고 카운팅한다.
5. 최소 횟수 이상인 쌍만 최종 결과에 남긴다.

핵심 성질: `{a,b}`가 3번 나타났다면 a와 b도 각각 최소 3번 나타나야 한다. 단일 상품부터 드문 항목을 제거해도 빈발 쌍을 놓치지 않는다. 이것이 downward closure다.

확인 질문: 왜 a 자체가 2번밖에 나오지 않았다면 a가 들어간 어떤 쌍도 3번 나올 수 없는가?

## 3단계: PCY는 어떤 필터를 더하는가

파일: `basket_mining/algorithms/pcy.py`

1. 상품 코드를 정렬해 로컬 정수 ID를 만든다. 반환값에는 원래 코드가 유지된다.
2. 첫 번째 패스에서 상품 빈도와 **모든 쌍**의 해시 버킷 빈도를 함께 센다.
3. 최소 횟수 이상인 버킷만 1인 압축 비트맵을 만든다.
4. 두 번째 패스에서는 두 상품이 빈발이고 해시 버킷도 빈발인 쌍만 카운팅한다.
5. 실제 쌍의 등장 횟수가 기준 이상인지 다시 검사한다.

해시 식은 `(i * 1_000_003 + j) % B`, i < j다. 예제의 ID a=0,b=1,c=2,d=3,e=4, B=5이면:

| 쌍 | 등장 횟수 | 버킷 |
|---|---:|---:|
| ab | 4 | 1 |
| ac | 3 | 2 |
| ad | 2 | 3 |
| bc | 3 | 0 |
| bd | 2 | 1 |
| cd | 1 | 4 |
| de | 1 | 3 |

버킷 카운트는 `[3,6,3,3,1]`이다. 기준 3이면 버킷 4만 제거된다. ad는 de와 충돌해 빈발 버킷에 있지만 실제로는 2번뿐이므로 마지막에 제거된다. 빈발 버킷이 곧 빈발 쌍은 아니다.

확인 질문: 버킷 수를 1로 줄이면 왜 최종 답은 그대로지만 필터 효과는 사라지는가?

비트맵: B=5이면 1바이트, B=9이면 2바이트가 필요하다. `bytearray`와 비트 연산으로 실제 1비트/버킷을 사용한다. 1차 패스 배열은 2차 패스 전에 해제한다.

## 4단계: 연관규칙

파일: `basket_mining/rules.py`

8개 바구니에서 a 5번, b 5번, ab 4번:

```text
Support(a,b)   = 4 / 8 = 0.5
Confidence(a→b) = 4 / 5 = 0.8
Lift(a→b)     = 0.8 / (5/8) = 1.28
```

`a→b`는 a가 들어간 바구니에 b도 들어갈 비율이다. 먼저 a를 산다는 뜻이나 a 때문에 b를 샀다는 뜻이 아니다. 장바구니 집합은 순서를 보존하지 않는다.

규칙 필터의 기본 정책은 Confidence 0.5 이상, Lift 1 이상이다. Lift 1 자체는 독립에 해당하므로 추천에 양의 연관성만 쓸 경우 경계 정책을 조정한다.

## 5단계: 삼중항

파일: `basket_mining/extensions/triples.py`

ab, ac를 합쳐 abc를 후보로 만들 때 bc도 빈발이어야 한다. 모든 2개 부분집합이 빈발인 삼중항 후보를 만든 뒤, 세 상품이 같은 바구니에 있는 횟수를 센다. 세 쌍이 모두 빈발이어도 세 상품이 함께 나타나지 않을 수 있으므로 최종 카운팅은 필수다.

3개 항목의 규칙은 a→bc, b→ac, c→ab, ab→c, ac→b, bc→a의 6방향이다. 모두 `rules.py`가 계산한다. 쌍 성능만 비교할 때는 `--max-size 2`로 확장 비용을 제외한다.

## 6단계: 실험과 설명

파일: `basket_mining/benchmark.py`

- 같은 데이터와 지지도에서 두 방법의 최종 결과가 같은지 확인한다.
- 필터로 줄어든 후보 **종류 수**와 카운팅 **횟수**를 구분한다.
- PCY가 느리더라도 해싱·비트맵 검사 비용과 후보 감소량을 함께 설명한다.
- 입력 읽기·정렬 시간은 공통 전처리이므로 현재 알고리즘 타이밍에서 제외한다.
- 메모리는 측정 범위를 적고, 자료구조 payload와 전체 프로세스 RAM을 혼동하지 않는다.

추천 실습: 예제에 바구니 하나를 추가하고, 지지도와 버킷 수를 바꾼 뒤 결과를 예측하고 실행한다. 그 다음 테스트의 전수계산 함수가 어떻게 다른 방식으로 정답을 만드는지 읽는다.
