## 1. 질문과 범위 (루브릭 25점)

### 질문

> 2009-12 ~ 2010-11 (1년 차) 거래에서 찾은 연관 규칙이 2010-12 ~ 2011-11 (2년 차)에도 성립하는가? 그리고 그 규칙이 장바구니에서 가린 상품을 인기 상품 기준선보다 더 잘 맞히는가?

장바구니(송장) 안에는 순서가 없다. 그래서 "다음 상품"이 아니라 "가린 상품"을 맞힌다.

### 왜 중요한가

소매점이 묶음 판매나 진열을 바꾸려면 규칙이 다음 시즌에도 성립해야 한다. 한 해에만 성립하는 규칙은 우연이거나 일회성 행사일 수 있다. 규칙이 인기 상품 추천보다 낫지 않다면 규칙 마이닝을 할 이유가 없다.

### 고정한 기준

이 기준은 `plan-v0.3` 태그로 커밋해 동결한다. 커밋 해시는 동결 후 이 줄에 적는다.

- 주 support 기준: **1%** (1년 차 장바구니 19,743개 중 198개 이상)
- 규칙 기준: **confidence ≥ 0.5, lift > 1**. lift > 1은 교재 §6.1.3의 interest(conf − P(j)) > 0과 같다
- 장바구니: 송장 하나 = 상품 코드의 집합 (같은 코드가 여러 줄이어도 한 번)
- 난수: `numpy.random.default_rng(seed)`
- support 2%, 0.5%, 0.25%는 PCY 성능 비교와 민감도 보고에만 쓴다

**사전 노출 고지:** 파일럿에서 1년 차 → 2년 차 유지율(71%)을 한 번 봤다. 그래서 H1의 판정 기준은 파일럿이 재지 않은 값(1년 차 안 분할 유지율)과 비교하는 형태로 정했다. 보고서에 이 사실을 적는다.

### 무엇이 답으로 인정되는가

| 가설 | 측정 | "예" 조건 |
|---|---|---|
| H1 시간 안정성 | 1년 차 → 2년 차 규칙 유지율 R_time과 1년 차 안 분할 유지율 R_split의 차이 | R_time ≥ R_split − 15%p |
| H2 예측 우위 | 2년 차 HitRate@5, 규칙 기반 − 인기 기준선 B0 | 가리기 seed 5개 모두에서 대응 bootstrap 95% 신뢰구간 하한 ≥ +2%p |
| H3 도구 에이전트 정확성 | 질문 30개 문항 정답률 (3회 실행 평균) | 도구 Solar ≥ 80%, 그리고 표 붙여 넣기 Solar 이상 |

조건을 못 넘으면 그 가설은 "아니오"다.

**H1 정의:**

- **R_split:** 1년 차 장바구니를 무작위로 반반 나눈다 (seed 0~9, 10회). 반쪽 A에서 같은 기준으로 규칙을 찾고, 반쪽 B에서 유지율을 잰다. 10회 평균이다. 시간 변화가 없을 때 표본 차이만으로 생기는 유지율 상한이다.
- **R_time:** 1년 차 전체 규칙이 2년 차에서 confidence ≥ 0.5, lift > 1을 만족하는 비율이다.
- **두 유지율 공통 규칙:**
  - 평가 쪽 support 조건은 두지 않는다
  - 규칙의 상품 중 하나라도 평가 쪽에 없으면 "유지 안 됨"으로 센다
  - 전건 상품이 평가 쪽 장바구니 1~19개에만 있으면 confidence가 불안정하다. 이런 규칙은 분모에서 빼고 개수를 따로 보고한다
- R_time이 R_split보다 15%p 넘게 낮으면 규칙이 시간에 따라 무너진다는 뜻이다. 2년 차 주문 행의 18.7%가 새 상품이라 실제로 실패할 수 있다.

**보조 보고 (판정 아님):**

- 1년 차와 2년 차 confidence의 Spearman 상관
- |conf₂ − conf₁| ≤ 0.1인 규칙 비율

**§1.2 본페로니 점검 (판정 아님, 3.3절):** 셔플 null로 추정한 우연 규칙 비율과, Fisher 정확 검정 + 본페로니 보정을 통과한 규칙 비율을 보고한다. null에서는 confidence ≥ 0.5 규칙이 거의 0개라 이것은 가설이 아니라 점검이다.

## 3. 방법과 정당화 (루브릭 25점)

### 3.1 빈발 항목집합 (MMDS 6장)

- **A-Priori (§6.2):** 1차 패스에서 상품 빈도를 센다. 2차 패스에서 빈발 상품끼리의 쌍을 삼각 배열로 센다.
- **PCY (§6.3.1):** 1차 패스에서 모든 쌍을 해시 버킷에 센다. 2차 패스는 두 상품이 모두 빈발하고 빈발 버킷에 속한 쌍만 센다.
  - 상품 코드를 정렬해 정수 번호 i < j를 매긴다
  - 해시: (i × 4,877 + j) mod B
  - Python `hash()`는 실행마다 바뀌므로 쓰지 않는다
  - 버킷 수 B는 2^16과 2^20 두 가지로 비교한다
- **교재의 메모리 단서:** PCY는 후보가 불규칙해 삼각 배열(쌍당 4바이트)을 못 쓰고 삼중 표현(쌍당 12바이트)을 쓴다. 그래서 후보를 2/3 이상 줄여야 2차 패스에서 이득이다.
  - 1차 패스의 버킷 배열도 메모리다. 2^20 버킷 × 4바이트 ≈ 4MB로, support 1%에서 A-Priori 삼각 배열(4 × 253,828 ≈ 1MB)보다 크다
  - 그래서 최대 메모리는 두 패스 중 큰 쪽으로 잰다
- **주 결과 (결정적, `results/pcy_compare.csv`):**
  - 2차 패스 후보 쌍 수
  - 빈발 버킷 비율
  - 교재식 이론 메모리: 패스별로 계산하고 최댓값을 쓴다
- **보조 결과 (환경 의존, `results/timings.csv`):**
  - 실행 시간과 `tracemalloc` 최대 메모리 (5회 중앙값과 범위)
  - CPU와 Python 버전을 같이 기록한다
  - 장표에는 "환경 의존" 표시를 붙이고 `slide_numbers.csv`의 검증 대상에서 뺀다
- 비교 수준: support 2%, 1%, 0.5%, 0.25%. 모든 수준에서 두 구현의 빈발 쌍이 같아야 한다.

**예상:** 이 규모에서는 A-Priori가 메모리와 시간 모두 충분할 가능성이 크다. 그렇게 나오면 그대로 보고하고 "이 데이터 크기에서는 A-Priori로 충분하다"를 방법 선택의 근거로 쓴다. PCY가 이기는 support 수준이 있으면 그 경계를 보고한다.

### 3.2 규칙과 예측 (H2)

- **규칙:** 빈발 쌍 {A, B}에서 A → B와 B → A를 만든다. 지표는 support, confidence, lift. H2에는 1년 차 규칙 전체를 거르지 않고 쓴다.
- **평가 장바구니:** 2년 차에서 상품 2개 이상인 장바구니 17,515개.
- **가리기:** 장바구니마다 상품 하나를 무작위로 가린다. 가리기 seed는 0~4로 5회 반복한다.
- **보이는 상품:** 가린 상품을 뺀 나머지다.
- **규칙 기반 추천:**
  - 후보: 보이는 상품을 전건으로 갖는 규칙의 후건. 보이는 상품은 후보에서 뺀다
  - 점수: 후보마다 confidence의 최댓값
  - 동점 처리: 1년 차 규칙 support가 큰 순, 그다음 상품 코드 순
  - 5개가 안 되면 B0 순서로 채운다
- **적중:** 가린 상품이 추천 5개 안에 있으면 적중이다.
- **기준선 B0 (인기 상품):** 1년 차에 가장 많은 장바구니에 들어간 상품 중 보이는 상품이 아닌 상위 5개.
- **기준선 B1 (support 기준 없는 규칙):** 1년 차의 모든 쌍 동시 출현 횟수로 P(y | x)를 구해 같은 방식으로 추천한다. 판정 대상은 아니다.
  - B1이 주 방법보다 나으면 support 기준이 정확도를 깎는다는 뜻이다. 그래도 주 방법을 쓰는 이유는 해석 가능성과 본페로니 통제다. 이 비용을 보고서에 적는다.
- **Bootstrap:** 평가 장바구니를 복원 추출한다 (1,000회, seed 0). 같은 장바구니의 (규칙 적중 − B0 적중)을 대응시켜 백분위 95% 신뢰구간을 구한다. 가리기 seed마다 따로 구한다.
- **층별 보고:** 장바구니 크기 사분위별 HitRate.
- **상품 교체 보고:** 가린 상품이 1년 차에 없던 비율과, 그런 장바구니를 뺀 HitRate. 판정은 전체 기준이다.

### 3.3 우연한 규칙 점검 (MMDS §1.2 본페로니 원리)

support 1%에서 함께 나타난 쌍 252,748개를 검사한다. 이만큼 검사하면 우연히 기준을 넘는 쌍이 생길 수 있다.

- **셔플 null:**
  - (장바구니, 상품) 쌍 전체에서 상품 열만 섞는다. 장바구니 크기와 상품별 등장 횟수는 그대로이고, 상품 사이의 관계만 깨진다
  - 한 장바구니에 같은 상품이 겹치면 겹친 자리만 다시 섞는다. 최대 100회 재시도하고, 남은 겹침 수를 기록한다
  - 1년 차를 100회 섞는다 (seed 0~99)
  - 보고 값: null 평균 규칙 수 ÷ 실제 규칙 수 = 추정 우연 규칙 비율
- **Fisher 정확 검정:**
  - 실제 1년 차 규칙의 쌍마다 2×2 분할표로 검정한다
  - 유의수준은 0.05 ÷ 252,748 (본페로니 보정)이다
  - 보고 값: 이 기준을 통과한 규칙 비율
- **용도:** 둘 다 점검이고 판정이 아니다. 기준은 1절에서 동결했다.
- **비용:** 1년 차 마이닝 1회가 1초 미만이라 100회도 몇 분이면 된다.

### 3.4 Solar 에이전트 (H3)

- **모델:** Upstage Solar (OpenAI 호환 chat completions, function calling 지원 모델). 11/17까지 접속 테스트를 한다. 모델 ID와 실행 날짜는 `results/agent_runs.jsonl`에 기록한다.
- **도구 (규칙 표만 읽는다. 에이전트는 수치를 직접 계산하지 않는다):**
  - `rules_for(product)`: 상품명 또는 코드로 관련 규칙 조회
  - `top_rules(min_support, min_confidence)`: 기준을 넘는 상위 규칙
  - `season_filter(period)`: 성수기 규칙. 1년 차 2009-12와 2010-11 장바구니(4,385개)로 따로 마이닝하고, null 100회도 돌린다
- **질문 세트:** 30개를 에이전트를 돌리기 전에 만든다.
  - 구성: 답이 있는 질문 24개, 함정 질문 6개 (없는 상품, 데이터에 없는 기간, 규칙이 없는 조합)
  - 작성자: 에이전트 담당이 아닌 데이터·평가 담당 2명
  - 정답지 `results/h3_answer_key.csv`: 문항마다 허용 도구 집합, 인용해야 할 수치, 함정이면 "답할 수 없음"
  - 성수기 문항은 4개다. `season_filter`를 빼게 되면 이 4문항을 양쪽 비교에서 모두 빼고 26문항으로 판정한다
- **문항 정답 기준:**
  - 정답지의 수치를 모두 ±0.005 안에서 인용하면 정답이다. 도구 Solar는 허용 도구 집합 안의 도구를 호출해야 한다
  - 함정 문항은 답할 수 없다고 말하면 정답이다
  - 분모는 정답지 수치다. 수치를 인용하지 않은 답은 틀린 것이다
- **비교 대상 (표 붙여 넣기 Solar):** 같은 모델에 규칙 표 CSV 전체를 프롬프트에 붙여 넣고 같은 질문을 한다. 규칙이 약 200개라 들어간다. 도구 호출이 표를 통째로 주는 것보다 나은지를 본다.
- **보조 보고:** 키워드 → 도구 규칙 라우터(LLM 없음)의 정답률, 도구 선택 정확도, Wilson 95% 신뢰구간.
- **실행과 채점:**
  - 두 방식 모두 temperature 0으로 3회 실행해 평균을 낸다
  - 채점자 2명이 따로 채점해 `results/h3_grades.csv`에 둘의 점수와 합의 점수를 남긴다. 불일치 건수도 보고한다
  - `run_all`은 이 두 CSV와 `agent_runs.jsonl`에서 H3 표를 만든다
- **에이전트가 없다면:** 사람이 규칙 수백 개를 표에서 직접 걸러야 한다. 에이전트는 질문을 도구 호출로 바꾸고 근거 수치와 함께 답한다.

### 3.5 고려했지만 버린 대안

| 대안 | 위치 | 버린 이유 |
|---|---|---|
| Multistage, Multihash | §6.3.2, §6.3.3 | PCY를 다듬어 후보를 더 줄이는 방법이다. PCY 후보 감소가 2/3에 못 미치면 이들도 얻을 것이 적고, 패스나 해시 수만 늘어난다 |
| SON, Toivonen 표본 알고리즘 | §6.4 | 데이터가 메모리에 다 들어가서 나눠 읽거나 표본을 쓸 이유가 없다 |
| 스트림 빈발 항목 | §6.5 | 데이터가 고정된 2년치다 |
| 쌍별 Fisher 검정 + 본페로니를 주 방법으로 | §1.2 | 규칙의 크기(confidence)가 아니라 유의성만 준다. support 1%의 쌍은 표본이 커서 약한 관계도 유의해진다. 그래서 점검으로만 쓴다 (3.3) |
| MinHash + LSH 유사 상품 | 3장 | Jaccard는 대칭이라 "A를 사면 B를 산다"는 방향이 없다. 상품 4,877개라 정확히 셀 수 있어 근사가 필요 없다 |
| 협업 필터링 (코사인, Jaccard 유사도) | 9장 | 대칭 유사도라 방향이 없고, 교재 방식은 고객을 사용자로 두는데 고객 ID를 분석 단위로 쓰지 않는다. 방향 있는 비교 대상은 B1로 둔다 |
| FP-Growth | 교재 밖 | 결과는 A-Priori와 같고, 과목 개념을 쓰는 조건에 맞지 않는다 |

## 4. 무엇을 버렸는가 (루브릭 25점)

**"결과가 바뀜"의 정의 (판정이 있는 줄 공통):** 다음 중 하나라도 해당하면 결과가 바뀐 것이다.

- H1이나 H2 판정이 뒤집힌다
- R_time이 10%p 이상 변한다
- HitRate 차이가 2%p 이상 변한다

판정 줄과 서술 줄을 구분한다. 서술 줄은 수치만 보고하고 판정하지 않는다.

| 버린 정보 | 질문과의 관계 | 확인 방법 | 종류 |
|---|---|---|---|
| 수량 | 질문은 "함께 사는가"라 정의상 무관하다. 다만 도매 대량 구매도 같은 무게로 센다 | 총수량 가중 support 상위 20개 규칙과 보통 상위 20개의 겹침 수 | 서술 |
| 큰 장바구니 (최대 1,108개) | 큰 장바구니 하나가 수십만 쌍을 만들어 규칙을 좌우할 수 있다 | 연도별 크기 상위 1%를 빼고 H1, H2 재실행 | 판정 |
| 가격 | 질문과 무관하다 | 해당 없음 | - |
| 고객 정체성 | 한 도매 고객의 반복 주문이 일반 규칙처럼 보일 수 있다 | 규칙마다 상위 5개 고객의 지지 비율. 50% 이상인 규칙을 빼고 H1, H2 재실행 | 판정 |
| 비회원 거래 (행 22.6%) | 고객 집중도 확인에서 빠진다 | 비회원 장바구니를 빼고 H1, H2 재실행 | 판정 |
| 송장 = 장바구니 | 한 고객이 같은 날 나눠 낸 주문(2,900건)은 다른 장바구니가 된다 | 같은 고객·같은 날 송장을 합친 장바구니로 H1, H2 재실행 | 판정 |
| 같은 줄 반복 (10,941건) | 집합으로 보므로 무관하다 | 해당 없음 | - |
| 장바구니 안의 순서 | 송장은 한 번에 결제되므로 순서 정보가 원래 없다 | 해당 없음 | - |
| 상품 교체 | 새 상품 651개는 예측할 수 없고, 사라진 상품 917개의 규칙은 자동으로 실패한다 | 3.2절 교체 보고, 사라진 상품이 든 규칙 수 | 서술 |
| support 1% 미만 상품 (롱테일) | 1년 차 상품 4,055개 중 713개만 남는다 | 커버리지(추천에 한 번이라도 나온 상품 수)를 B0, B1과 비교 | 서술 |
| confidence < 0.5 또는 lift ≤ 1 규칙 | 약하거나 음의 관계는 버린다 | confidence 0.3 기준의 규칙 수와 R_time | 서술 |
| 상품 1개 장바구니 (1년 차 1,708개) | 규칙을 만들지 않지만 support 분모에는 들어간다 | 분모에서 뺀 규칙 수 | 서술 |
| 수량·가격 ≤ 0 행 (6,014행) | 반품이나 오류로 보고 뺀다 | 질문과 무관하다고 본다. 내용은 확인하지 않는다 | - |
| 상품이 아닌 코드 (4,699행) | `POST`는 장바구니 1,851개에 있어 남기면 거의 모든 상품과 규칙을 만든다 | 질문이 상품 간 관계라서 무관하다 | - |
| 소문자 접미사 통일 (173개 코드) | 170개가 기존 대문자 코드와 합쳐진다. 같은 상품이라고 가정한다 | 모른다. 확인하지 않는다 | - |
| 상품 설명, 색상 변형 | 같은 코드의 다른 설명은 합치고, 색상만 다른 코드는 따로 센다 | 모른다. 확인하지 않는다 | - |
| 취소와 반품 | 취소된 구매를 동시 구매로 세지 않으려고 버린다 | 원 송장과 연결할 키가 없어 영향은 모른다. 취소 행 중 규칙 상품 비율만 보고 | 서술 |

## 5. 재현 가능성 (루브릭 15점)

```text
.python-version              3.14
requirements.txt             pip freeze로 == 고정 (11/10)
scripts/download_data.py     다운로드와 SHA 확인 (완료)

src/null_model.py            셔플 null, Fisher 검정
src/evaluate.py              H1, H2, 민감도 분석
src/agent.py                 Solar 에이전트. --eval 로 H3 실행 (API 키 필요)
src/run_all.py               키 없이 도는 전체 실행. --only <ID> 로 하나만
tests/test_textbook.py       교재 예제로 A-Priori, PCY 결과 확인
tests/test_pcy_hash.py       두 번 실행해 버킷 수가 같은지 확인
```

**그림·표 ID와 명령:**

| ID | 내용 | 명령 |
|---|---|---|
| T1 | 전처리 단계별 행 수 | `python -m src.run_all --only T1` |
| T2 | A-Priori vs PCY 비교 | `--only T2` |
| T3 | H1 (R_time, R_split), 본페로니 점검 | `--only T3` |
| T4 | H2 HitRate, 신뢰구간, 층별 | `--only T4` |
| T5 | 민감도 분석 (4절 판정 줄) | `--only T5` |
| T6 | H3 정답률 | `--only T6` (저장된 기록에서) |
| F1 | 월별 장바구니 수 | `--only F1` |
| F2 | 1년 차 vs 2년 차 confidence 산점도 | `--only F2` |

- 깨끗한 체크아웃에서 `python scripts/download_data.py && python -m src.run_all`로 위 모든 표와 그림을 만든다. API 키가 필요 없다.
- H3를 새로 돌리려면 `.env`에 키를 넣고 `python -m src.agent --eval`을 실행한다. 결과가 달라질 수 있다고 보고서에 적는다.
- 시드:
  - 가리기 0~4, bootstrap 0, null 0~99, 분할 0~9
  - PCY 해시는 결정적 공식이라 시드가 없다
- 보고서의 그림과 표마다 위 명령을 바로 아래에 적는다.
- 결정적인 결과(후보 쌍 수, 규칙 수, 유지율, HitRate)가 주 결과다. 실행 시간과 메모리는 보조이고 `results/timings.csv`에만 둔다.
- `.env`와 `data/`는 `.gitignore`로 막는다 (확인 완료).

## 변경 기록

**v0.2 → v0.3** (리뷰 2회차 평균 81.0점 반영)

- **H1:** 셔플 null 비교는 항상 통과해서 가설이 아니었다. 1년 차 안 분할 유지율(R_split, 파일럿이 재지 않은 값)과 비교하는 H1으로 바꿨다. 전건 상품이 평가 쪽 장바구니 20개 미만이면 분모에서 뺀다. null과 Fisher 검정은 점검으로 내렸다
