# 알고리즘 정리

코드를 읽는 순서는 `apriori.py` → `pcy.py` → `rules.py` → `triples.py`가 편하다. 먼저 `examples/baskets.json`의 8개 바구니로 결과를 확인하면 된다.

## A-Priori

`basket_mining/algorithms/apriori.py`

1. 첫 번째 패스에서 상품별 등장 횟수를 센다.
2. 최소 횟수 이상인 상품만 남긴다.
3. 두 번째 패스에서 남은 상품끼리 쌍을 만들고 센다.
4. 최소 횟수 이상인 쌍을 반환한다.

ab가 3번 등장했다면 a와 b도 각각 최소 3번은 등장해야 한다. 따라서 a가 2번뿐이면 a가 포함된 쌍은 더 세지 않아도 된다.

입력 정렬과 중복 제거는 `models.py`에서 한다. 한 바구니에 a가 여러 개 있어도 한 번으로 센다.

## PCY

`basket_mining/algorithms/pcy.py`

첫 번째 패스에서 상품 빈도와 쌍의 해시 버킷 빈도를 함께 센다. 빈발 버킷만 비트맵에 남긴 뒤, 두 번째 패스에서 다음 조건을 모두 만족하는 쌍을 센다.

- 두 상품이 모두 빈발 상품이다.
- 쌍이 속한 버킷도 빈발 버킷이다.

해시는 `(i * 1_000_003 + j) % B`다. 상품 코드를 정렬해 만든 정수 ID를 쓰며 i < j다. 예제에서 a=0, b=1, c=2, d=3, e=4이고 B=5이면 다음과 같다.

| 쌍 | 등장 횟수 | 버킷 |
|---|---:|---:|
| ab | 4 | 1 |
| ac | 3 | 2 |
| ad | 2 | 3 |
| bc | 3 | 0 |
| bd | 2 | 1 |
| cd | 1 | 4 |
| de | 1 | 3 |

버킷 카운트는 `[3, 6, 3, 3, 1]`이다. 기준 3이면 버킷 4가 제거된다. ad는 de와 충돌해서 버킷 필터를 통과하지만 실제 빈도는 2이므로 마지막에 빠진다. 빈발 버킷이라고 그 안의 모든 쌍이 빈발인 것은 아니다.

비트맵은 `bytearray`로 압축한다. 버킷 5개는 1바이트, 9개는 2바이트가 필요하다. 첫 패스의 버킷 카운터는 두 번째 패스 전에 해제한다. 다만 팀 테스트에서 버킷 값을 확인할 때는 진단용 복사본을 남긴다.

## 연관규칙

`basket_mining/rules.py`

8개 바구니에서 a=5, b=5, ab=4라면:

```text
Support(a,b)    = 4 / 8 = 0.5
Confidence(a→b) = 4 / 5 = 0.8
Lift(a→b)       = 0.8 / (5/8) = 1.28
```

a → b는 a가 있는 바구니에 b도 있는 비율을 나타낸다. 구매 순서나 인과관계를 뜻하지 않는다.

## 삼중항

`basket_mining/extensions/triples.py`

ab와 ac를 합쳐 abc 후보를 만들 때 bc도 빈발인지 확인한다. 세 쌍이 모두 빈발이어도 abc가 같은 바구니에 함께 있지는 않을 수 있으므로 실제 횟수를 다시 센다.

두 알고리즘 모두 이 확장 코드를 사용한다. 쌍 탐색 성능만 비교할 때는 `--max-size 2`를 쓴다.

## 실험에서 볼 것

`basket_mining/benchmark.py`

최종 답이 같은지 먼저 확인하고, 후보 종류 수와 카운팅 횟수가 얼마나 줄었는지 본다. PCY는 해싱 비용이 추가되므로 후보가 줄어도 느릴 수 있다. 시간은 워밍업 후 반복 측정하고, 메모리는 별도 실행에서 측정한다.

예제의 지지도와 버킷 수를 바꿔 예상 결과와 비교해 보면 각 필터가 하는 일을 확인할 수 있다.
